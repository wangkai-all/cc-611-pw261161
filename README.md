# 签到 / 工单 投入归属分析

签到与任务工单分开记录。有人同一时段切换两个任务或跨活动支援时，**归属器**先把重叠时段拆成最小不可再分段并按规则分配（每段权重和恒为 1），再交**统计端**汇总总时长与投入 —— 同一人的总时长不因重叠重复计数。工单撤回后旧报告保留，并输出受影响范围。

## 运行

```bash
node server.js          # 读取 PORT（默认 3000），绑定 127.0.0.1
PORT=8123 node server.js
node --test             # 24 个用例，覆盖正常与异常路径
```

打开 `http://127.0.0.1:3000`，页面上可执行三个操作（数据全部走服务端真实处理流程）：

| 按钮 | 接口 | 说明 |
| --- | --- | --- |
| 分析原投入量 | `POST /api/analyze` | 按所选归属方法跑归属器+统计端，生成报告 |
| 撤回一张工单 | `POST /api/revoke` | 标记工单 revoked，保留旧报告，输出受影响范围 |
| 查看重叠拆分 | `GET /api/overlap` | 展示归属器切出的最小时段及每份权重 |

业务结果区带 `data-evidence-result` 属性，值随操作变化（如 `analyze:R1`、`revoke:WO-2:R1->R2`、`overlap:R2`），便于核对操作前后内容。

## 归属方法

- `completed-ratio` 按完成任务比例：重叠区按各工单 `progress` 比例分配（全为 0 时均分）。
- `primary` 按主责时间归属：重叠区全归 `primary` 主责工单（无主责时均分）。

## 规则与异常处理

- 工单超出签到时段的部分被裁剪，并在报告 `anomalies` 中记录。
- 已撤销工单不参与新一轮归属，但原始数据与旧报告（`GET /api/reports/:id`）保留。
- 非法输入返回明确错误：结束时间不早于开始时间、完成比例越界、未知归属方法 → 400；工单不存在 → 404；重复撤回 → 409。

## 结构

```
server.js          HTTP 层（仅内置模块）
src/engine.js      归属器（拆重叠区）+ 统计端（总时长/投入），纯函数
src/store.js       数据集 + 报告历史 + 撤销/受影响范围
src/sampleData.js  合成样例（含跨活动支援、同时段双任务、超出签到的工单）
public/            页面（原生 JS，结果区带 data-evidence-result）
test/              node --test 用例
```
